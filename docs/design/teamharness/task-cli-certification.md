## 二、任务集

### 1. 简单任务

Python 标准库实现 CSV 数据汇总：校验固定列、按类别统计行数及金额，金额使用精确
十进制规则，输出确定性排序的 JSON；提供 CLI、测试和简短 README。
单执行子任务，不强制为简单工作额外拆分开发、QA、文档任务。

独立验收覆盖正常输入、空数据、顺序变化、负金额及非法金额。用户可见需求明确输入
域和错误行为；隐藏数据只验证已声明规则，不增加需求。参考答案由验收程序计算。

### 2. 复杂任务

Python 标准库账单与退款汇总小项目，保留四个执行节点：

- A：实现账单读取模块 `transactions.py`，发布模块、整数分字段说明与测试。
- B：实现退款读取模块 `refunds.py`，发布模块、整数分字段说明与测试；与 A 独立并行。
- C：获取 A/B 已验收的确定版本模块，复用公共读取函数，实现净额汇总 CLI、结果及 README。
- D：对 C 做独立验证并提交测试证据；不修改已验收的上游输入。

覆盖并行分配、依赖推进、跨 Task 文件引用、中间产物、独立验收及原会话报告。
隐藏验收覆盖多次退款、未匹配退款、顺序变化和非法行；精确舍入及错误处理规则在
正式任务中声明。具体输入输出以 `tests/task-protocol/cases/` 两份任务说明为准。

正式运行前冻结可见 spec、输入数据、隐藏 oracle、超时阈值和文件摘要。

隐藏检查包括大整数分精度、负金额与负零、CSV 引号/Unicode、空数据、输入重排、
两个输入的非法字段、多次/全额/超额退款与未匹配退款。复杂任务分别调用两个公开
读取函数检查返回值与 ValueError 行为，并替换其返回数据，确认 CLI 实际消费这些
函数。交付的 unittest 必须至少执行一项且通过，不能把空发现当作测试成功。

本地验收器自测使用预制答案回放，并故意注入错误金额、错误输出和绕过模块的行为，
证明判定器能拒绝这些错误；这不代表 Agent 实现了任务，也不代表 Harness 认证。
验收器和隐藏数据不得提供给 Agent。业务结果之外，仍须分别核验 Leader 验收、
来源会话报告/真实产物、上下文事实及 Trace；业务通过不能替代完整交付证据。

## 三、重复运行与故障覆盖

每个新协议环境组合的正常认证至少运行：简单任务 10 次，复杂任务 10 次。
旧 main 仅作为已有对照，不继续扩充样本。
相同任务内容使用新的请求与 Task ID 独立执行，保留原来完成记录；不能复用终态任务
伪造重复执行。分别记录团队/会话是否全新、缓存是否预热，不混合口径。

另行验证同一请求、事件或操作 ID 的重复投递，确认不会重复创建、执行副作用或回告。
这与“同一任务内容反复执行”是两类测试，不能互相替代。

共享协议与恢复用例还必须覆盖：丢失或延迟通知、上传失败、提交响应未知、原生进程
重启、旧提交迟到、取消/重新分配，以及业务验收拒绝后的合法返工。故障场景单独
报告，不混入正常样本制造耗时或成功率改善。

## 四、判定与统计

成功的单次运行必须同时满足：

1. Agent 通过本轮公共协议执行，没有手工改状态、临时提示修正或人工补文件。
2. 主子任务实际执行和验收记录完整；独立业务 oracle 通过。
3. 文件存在、确定版本可读、大小与摘要正确；输入未被越权修改。
4. 原始 Manager 会话实际出现正确最终报告，以首跳派单 Agent 身份回告，并展示可访问
   的确定版本产物；报告、附件和实际投递回执均有证据。派单 Agent 的原会话上下文
   同步记录已发送事实，不额外唤醒模型或重复转发。
5. 发送方框架自动识别结构化工具回执，并将任务状态、自动通知状态、已确定的接收节点
   与下一步动作注入当前上下文；不依赖 Agent 解析，流式片段/失败/异任务/重复回执不误注入。
   Agent 不重复通知，不把“已入队”说成“已接单”，返回不要求感知 Controller。
6. Trace 可读且能关联相关 Agent、任务/会话；缺失的调用与 token 不能记成零。

记录每次入口时间、首次派发、ACK、执行、提交、验收和原会话回报时间。统计全部
运行的完成/失败/超时，另报成功样本的 P50/P95；超时是删失数据，不伪装成完成时间。
记录协作工具调用、模型请求、输入输出 token、自动重试、人工介入和失败分类。

第一种 Harness 认证要求同一冻结候选的简单/复杂各 10 次均干净成功，且共享故障与
恢复门禁通过；这里的成功对应上述完整交付质量门禁，耗时目标另行报告，不能用质量
通过掩盖性能未达标，也不能用性能达标掩盖质量失败。20/20 只代表通过这批验收，不证明生产成功率达到 100%；报告样本量
与统计不确定性。发现问题后保留失败记录，修复并生成新候选，重新执行完整认证批次。
基线失败也全部保留，不通过反复重跑只选成功结果。

耗时与调用改善只有在基线、候选配置一致且验收等价时才计算。先前的提升区间属于
工程假设，必须用实测替换，不能作为预先填写的结果。认证进度逐组合报告，禁止把
一种 Harness 的通过推广成六种或全部异构组合通过。
