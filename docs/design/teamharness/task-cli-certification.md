## 2026-11-22 推进复盘与收敛要求

已确认的验证缺口：

- QwenPaw 新增模型中间件使用了 async generator，而真实 SDK 要求 await 返回。
  原检查直接迭代中间件，复现了错误的调用方式；应通过实际 Agent.reply/model 边界验证。

  finish 却只接受 active；内存夹具没有模拟真实状态转换。该边界须用真实 Python→Go API 验证。

  原会话在 0.785 秒公开报错，观察器只等待 Task 终态，持续到 294.44 秒；该等待不能算业务耗时。

  span 回查为零，追踪验收未通过。配置、连通、真实 span 回查必须分开记录。
- 从仍在修改的工作区构建导致镜像内容与声明的提交不一致；冻结源必须使用明确的 Git

公共协议的业务判断只由公共 Task 层作出。Task execution、消息受理账本、canonical

公共判断。阻止未知操作重复执行与恢复后完成交付是两个验收结果，不能相互替代。

每轮冻结同一源码、镜像、模型、资源和输入，同种 Harness 执行三次简单任务与三次复杂任务。

基础镜像及后续构建所需依赖缓存。

同种 Harness 的每类请求先单发一次，再同时下发两条。混合批次保留三并发验证。每条都有独立原始 Matrix 事件，正文不变；
串行、双并发、三并发分别统计成功率与耗时。原请求到建单、派发到 ACK、ACK 到提交、
提交到验收分列；这些间隔含传输、调度或推理，不能直接命名为纯排队时间。

调度。名义三并发若只建立两个任务，须同时报告请求数与实际建单数，不视为三任务验证。

## 二、任务集

### 1. 简单任务

Python 标准库实现 CSV 数据汇总：校验固定列、按类别统计行数及金额，金额使用精确
十进制规则，输出确定性排序的 JSON；提供 CLI、测试和简短 README。
Leader 自行决定是否以及如何拆解。验收看任务是否完结、原会话回告，以及是否交付真实产物。

独立验收覆盖正常输入、空数据、顺序变化、负金额及非法金额。用户可见需求明确输入
域和错误行为；隐藏数据只验证已声明规则，不增加需求。参考答案由验收程序计算。

### 2. 复杂任务

Python 标准库账单与退款汇总小项目，交付账单和退款读取模块、复用这两个模块的
净额汇总 CLI、README、测试与验证报告。Leader 自行决定节点数量、分工和实际依赖。
业务验收覆盖多次退款、未匹配退款、输入重排、空数据及非法行。

后续同种和交叉 Harness 批次统一使用 `tests/task-protocol/cases/requirements-only/`，
派单只描述业务需求与交付标准。验收核对实际执行节点是否通过 Leader 验收、主任务
是否正常完成、实际产物是否回到原会话，以及协作回执和 Trace。可记录实际拆解和
耗时，无固定节点数、角色安排或依赖图要求。业务 oracle 继续单列。
旧用例与旧口径留作历史记录，已派发的请求及其结果不改写。

### 3. 独立业务验收器

`tests/task-protocol/run_oracle.py` 对已下载并校验摘要的项目产物创建独立快照，只将
快照和 `business_oracle.py` 挂载到临时容器，不挂载 Agent 工作区、凭据或仓库。

超时后按本次容器身份清理。验收输出记录精确镜像 ID、验收器 SHA256、产物摘要和逐项结果。

```sh

```

隐藏检查包括大整数分精度、负金额与负零、CSV 引号/Unicode、空数据、输入重排、
两个输入的非法字段、多次/全额/超额退款与未匹配退款。复杂任务分别调用两个公开
读取函数检查返回值与 ValueError 行为，并替换其返回数据，确认 CLI 实际消费这些
函数。交付的 unittest 必须至少执行一项且通过，不能把空发现当作测试成功。

本地验收器自测使用预制答案回放，并故意注入错误金额、错误输出和绕过模块的行为，

验收器和隐藏数据不得提供给 Agent。业务结果之外，仍须分别核验 Leader 验收、

另行验证同一请求、事件或操作 ID 的重复投递，确认不会重复创建、执行副作用或回告。

## 四、判定与统计

协议成功的单次运行必须同时满足：

1. Agent 通过本轮公共协议执行，没有手工改状态、临时提示修正或人工补文件。
2. 主子任务实际执行和验收记录完整；独立业务 oracle 仍执行，结果另列，不作为协议成功前提。
3. 文件存在、确定版本可读、大小与摘要正确；输入未被越权修改。
4. 原始 Manager 会话实际出现正确最终报告，以首跳派单 Agent 身份回告，并展示可访问
   的确定版本产物；报告、附件和实际投递回执均有证据。派单 Agent 的原会话上下文
   同步记录已发送事实，不额外唤醒模型或重复转发。
5. 发送方框架自动识别结构化工具回执，并将任务状态、自动通知状态、已确定的接收节点
   与下一步动作注入当前上下文；不依赖 Agent 解析，流式片段/失败/异任务/重复回执不误注入。
   Agent 不重复通知，不把“已入队”说成“已接单”，返回不要求感知 Controller。
6. Trace 可读且能关联相关 Agent、任务/会话；缺失的调用与 token 不能记成零。

记录每次入口时间、首次派发、ACK、执行、提交、验收和原会话回报时间。统计全部
运行的完成/失败/超时，另报成功样本的 P50/P95；超时是删失数据，不伪装成完成时间。
记录协作工具调用、模型请求、输入输出 token、自动重试、人工介入和失败分类。

每种 Harness 要求同一冻结候选的简单三组、复杂三组均干净协议成功，且共享故障与
恢复门禁通过；业务实现质量和耗时目标另行报告。同种 Harness 的 6/6 只代表通过该批协议
验收，不证明生产成功率达到 100%；报告样本量与统计不确定性，以及包括环境故障、
失败和人工恢复的总尝试数。环境故障恢复单列，保留原失败与介入，不计干净成功；
同一候选需另用新请求补足干净次数。发现协议实现问题后保留失败记录，修复并生成
新候选，重新执行完整认证批次。业务实现问题不触发协议重建或无意义重跑。
基线失败也全部保留，不通过反复重跑只选成功结果。

耗时与调用改善只有在基线、候选配置一致且验收等价时才计算。先前的提升区间属于
工程假设，必须用实测替换，不能作为预先填写的结果。认证进度逐组合报告，禁止把
一种 Harness 的通过推广成六种或全部异构组合通过。

保留运行记录后，可用以下只读命令按运行时源码、Harness 组合和场景汇总：

```sh
python3 tests/task-protocol/summarize_runs.py /absolute/path/to/evidence/runs --source FULL_RUNTIME_COMMIT
```

汇总同时列出已发送、已验收、失败和待验收样本；成功率分母明确使用已验收样本数，
未完成项单列。P50/P95 用完整质量通过样本的真实交付耗时按 nearest rank 计算；
原始超时和迟到质量通过可同时出现。Trace 不完整或字段缺失时保留 unknown，不补零；
不自动合并不同源码或组合，不把这个统计结果声明为 Harness 认证。
`protocolPassed` / `protocolDeliverySeconds` 单列协议结果及耗时；`businessOraclePassed`
与 `businessOracleFailed` 保留业务结果。旧 quality 字段仍代表历史综合交付质量口径，
不能用其失败代替新的协议判定，也不能删掉业务失败以制造业务质量提升。
